# Beetroot Traffic Light (Module 02)

We are creating a **traffic light program** for an STM32 microcontroller. The firmware
controls a vehicle traffic light and a pedestrian light at a crossing with a
**pedestrian call button**. Vehicles have green by default; the pedestrian phase
starts only after a pedestrian presses the button.

## Hardware

| Parameter       | Value                          |
|-----------------|--------------------------------|
| MCU             | **STM32F411CEU6**              |
| Family / Core   | STM32F4, ARM Cortex-M4F        |
| Package         | UFQFPN48                       |
| Flash / RAM     | 512 KB / 128 KB                |
| System clock    | 16 MHz (HSI)                   |

## Algorithm

### Phases

| # | Vehicle light  | Duration                       | Pedestrian light                     |
|---|----------------|--------------------------------|--------------------------------------|
| 1 | Green          | at least 30 s (until a call)   | Red                                  |
| 2 | Green blinking | 3 s                            | Red                                  |
| 3 | Yellow         | 2 s                            | Red                                  |
| 4 | Red            | 30 s                           | Green ~25 s, then Red for the last 5 s |
| 5 | Red + Yellow   | 1 s                            | Red                                  |

After phase 5 the controller returns to phase 1 and the 30-second minimum green
timer for vehicles starts again. A full cycle with a pedestrian call takes at least
**66 seconds**.

```
                 button pressed AND minimum green (30 s) elapsed
 ┌─► GREEN (≥ 30 s) ────────────────────────────► GREEN BLINKING (3 s) ─┐
 │      ▲  │ no call: stay green                                         │
 │      └──┘                                                             ▼
 │                                                                 YELLOW (2 s)
 │                                                                       │
 └──── RED + YELLOW (1 s) ◄──── RED (30 s, pedestrians: green) ◄─────────┘
```

### Phase details

1. **Green (minimum 30 s).** The idle state. 30 seconds is the *minimum guaranteed*
   green time for vehicles. If the button is not pressed, the green stays on
   indefinitely (31st, 50th, 120th second and so on).
2. **Green blinking (3 s).** The first warning to drivers that the pedestrian phase
   is about to start.
3. **Yellow (2 s).** Vehicles stop before the stop line.
4. **Red (30 s).** Vehicles have red and pedestrians get green. The pedestrian green
   is shorter than the phase (about 25 s); the last 5 seconds are a clearance
   interval so pedestrians can finish crossing before vehicles move.
5. **Red + Yellow (1 s).** Drivers prepare to start. Then the controller returns to
   phase 1.

### Pedestrian button

The controller stores a button press as a **pedestrian request** and serves it
according to the current phase:

| Button pressed during            | Behaviour                                                                 |
|----------------------------------|---------------------------------------------------------------------------|
| Phase 1, green on less than 30 s | The request is remembered; the switch starts once the 30 s minimum ends (e.g. pressed at 10 s → switch after another 20 s). |
| Phase 1, green on 30 s or longer | The switch to phase 2 starts immediately.                                 |
| Phases 2–3                       | The pedestrian phase is already coming; the press is served by this cycle. |
| Phases 4–5                       | The request is queued. The current red is **not** extended: the cycle finishes, returns to phase 1, waits the mandatory 30 s of vehicle green, and only then runs phases 2–5 again. |


## Build

The project is generated by STM32CubeMX with the CMake toolchain.

```sh
cmake --preset Debug
cmake --build --preset Debug
```
